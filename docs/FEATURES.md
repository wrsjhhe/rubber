# 功能需求

本文描述目标，实际状态只维护在 [PROGRESS.md](PROGRESS.md)。编号保持稳定，供开发和审核共同引用。

## 应用范围

提供独立 C++ Vulkan 渲染库，用于仿真资产验证器、仿真测试系统和视觉传感器图像生成。支持无窗口使用；GLFW、ImGui 和示例资产不是核心库必要依赖。优先建立扩展框架，再增加传感器模型和真实感功能。

## 通用规格约定（F11 起适用）

### 单位与坐标系

- 长度单位米，时间单位秒，光轴沿相机空间 **-Z**；`PerspectiveCamera::projection` 为右手系、深度范围 [0,1]（`GLM_FORCE_DEPTH_ZERO_TO_ONE`）。
- 像素坐标 `(u, v)`：`u` 向右、`v` 向下，`(0,0)` 是左上角像素中心；归一化坐标 `x = (u - cx) / fx`、`y = (v - cy) / fy`。
- 米制深度指沿光轴的 `-Z` 分量（不是欧氏距离），与现有 `Channel::MetricDepth` 一致。
- 所有标定参数（fx/fy/cx/cy、畸变系数、噪声参数）都进 `SensorCalibration` 或 `Observation`，不允许只存在于着色器常量里：观测必须能独立复算像素映射。

### 真值与传感器输出

`ChannelSemantic::groundTruth` 的判据收紧为：**只由场景几何、材质与相机标定决定，不随抗锯齿抖动、曝光积分、噪声、天气、上采样/超分改变**。因此：

- 新增的传感器效应不得写回真值通道。要么写入新的通道（语义表登记 `groundTruth=false`），要么作为处理链的派生输出。
- 真值通道的"真"还包括索引一致：畸变重采样后的深度/标签仍算真值（是同一批几何量的重排），但必须满足"值集合不变"（见 F11 门槛）。
- `Observation::result()` 的像素与 `calibration()` 必须指向同一次采样；传感器效应的开关状态也进观测，下游不能靠"猜"。

### 确定性与可复现

- 任何随机量（噪声、粒子、抖动、排序平局）都由 `(seed, 帧序号, 相机或视图标识)` 决定；同一输入的两次运行必须逐字节相同，跨进程重启亦然。
- 并行实现不得改变结果：归约顺序、排序键的平局处理都必须固定。确定性测试用两次运行逐字节比较，不用"统计上接近"。
- 时间驱动的东西只认 `SampleTime::time`，不认墙钟；暂停推进时间时画面必须静止（粒子类除外其定义见 F14）。

### 质量度量

- 图像指标：SSIM 用 8×8 高斯窗口、仅 RGB、在 sRGB 编码后计算；PSNR 按 8 bit 峰值。参考图入库到 `example/preview/ref/`，命名 `<功能>-<场景>.png`，与 `tools/pngdiff.py` 的字节差异一起报告。
- 像素级断言优先用"逐字节相同"或"值集合相同"，统计指标只用于噪声类与重建类。
- 每项的门槛数值在首次实现时校准并写回本文；调整门槛需要审核同意，不能在实现里悄悄放宽。

### 性能度量

- 环境：Windows 11、RTX 3080 Ti、VS2022 Release、1920×1080、默认画质、TAA 开。
- 方法：预热 10 帧、采样 100 帧；每 pass 用 `vkCmdWriteTimestamp` 取 GPU 时间，报告**中位数**，并给出 p95（p95 ≤ 1.5× 中位，否则视为不稳定）；CPU 提交时间单独统计、不混入 GPU 预算。
- 工具：`gallery --bench` 输出每 pass 中位/p95 与全帧时间。**该模式在 M7 内交付**；在此之前性能门槛记为"待测量"，不得宣称达标。
- 每项的门槛是"新增 pass 的中位时间"与"全帧增量"两个数，都要报。

### 立项交付物

每个里程碑必须交付：规格细化（本文对应节若有变化先改这里）、实现、CTest 设备测试、缺陷注入记录（每条门槛至少一个反例）、`--validation` 0 条、`gallery --smoke` 与截图比较、PROGRESS 的状态与缺项更新。缺任何一项都按未完成处理。

## F11 镜头畸变（M7）

### 范围

针孔 + Brown-Conrady 径向/切向畸变的单向映射（世界 → 像素含畸变），以及渲染侧的重采样。鱼眼、全景、逐像素查找表不在本项。

### 接口

- `struct LensDistortion { float k1 = 0, k2 = 0, k3 = 0, p1 = 0, p2 = 0; bool enabled() const; }`，由 `PerspectiveCamera` 携带（或 `View` 级别的覆盖，取更具体者）。
- `SensorCalibration` 增加 `distortion`；`calibration().project(world)` 返回**含畸变**的像素坐标；`projection()` 仍是针孔矩阵（光栅化在无畸变空间进行，见下）。
- 新增 `undistort(pixel) -> pixel`（牛顿迭代，5 次或 1e-8 收敛），供标定与测试复算。

### 语义与算法

- 归一化后先径向后切向：
  `r² = x² + y²`；`radial = 1 + k1r² + k2r⁴ + k3r⁶`
  `x_d = x·radial + 2p1xy + p2(r² + 2x²)`；`y_d = y·radial + p1(r² + 2y²) + 2p2xy`
  `u = fx·x_d + cx`，`v = fy·y_d + cy`。
- 渲染路径：几何、光照、时序解析、颜色变换都在**无畸变**空间完成（TAA 的抖动与运动向量因此不需要改约定），最后加一个 `lens` pass 按上述公式反向采样到畸变图像空间。
- 通道处理：颜色类（Color/Hdr/Resolved/AlbedoMetal/NormalRough）双线性（法线重归一化）；`MetricDepth`/`HardwareDepth`/`InstanceId` 用**最近点**（标签绝不能插值混合）。目标像素落在源域外时按 `ChannelSemantic::background` 填充（0/0 标签），不允许采样到相邻行的内存。
- 调试图（`Channel::Debug`）保持无畸变：它诊断的是 G-buffer 与光照，不是传感器成像；此点写进文档，避免与 Color 对不齐时被当成缺陷。
- 畸变是相机的确定性属性，不影响历史失效判定，也不改 `Resolved` 的内容（它只是重采样）。

### 验收门槛

1. **标定一致**：20×20 标定板已知 3D 点，`calibration().project()` 与 `lens` pass 输出的实际像素位置差 ≤ 0.5 px（在 r ≤ 0.9·min(fx,fy) 内）。
2. **解析位移**：`k1=0.12, k2=-0.03` 时，半径 0.8·min(fx,fy) 处的径向位移与公式计算差 ≤ 1e-3 px。
3. **直线弯曲**：无畸变的直边在开启畸变后，横向偏移沿半径单调且与解析值差 ≤ 0.2 px；关闭畸变时直边残差 ≤ 1e-3 px（不得引入无意位移）。
4. **最近点**：`InstanceId` 的取值集合与无畸变帧的集合相同（多集相等），边界 1 px 内不出现两个标签的混合值；`MetricDepth` 同理，值集合相同。
5. **边界填充**：目标像素落在源域外时取背景值（颜色 0、深度 0、标签 0），`--validation` 0 条（无未初始化读取）。
6. **真值独立**：开关畸变时 `Resolved` 逐字节相同（畸变只发生在最后的重采样），`MetricDepth`/`InstanceId` 的重采样只做重排不做混合。
7. **两相机**：同一快照、不同畸变系数的两台相机各自正确，互不影响历史。

### 性能门槛

`lens` pass 中位 ≤ 0.8 ms；全帧增量 ≤ 5%。报告分辨率 1080p。

### 不做

鱼眼/全景投影、外部畸变查找表、自动标定（从图像反解系数）、畸变与 TAA 的联合重投影优化。

## F12 曝光/运动模糊（M8）

### 范围

全局快门的曝光积分与相机运动模糊；滚动快门的逐行读出。物体自身运动模糊需要逐物体速度通道，不在 v1（见"不做"）。

### 接口

- 已有 `SampleTime{time, duration}`：`duration` 从"元数据"升级为真实的积分区间 `[time, time + duration]`；`duration == 0` 保持当前单帧行为，全部现有测试的结果不得改变。
- `struct ShutterModel { enum Kind { Global, Rolling } kind; double readoutSeconds; }`，挂在相机上。
- `RenderOptions::subframes`（1—16，默认 4）；`Channel::Resolved` 变为积分结果，其 A 分量改为子帧米制深度的加权平均并标注"非真值"。
- 真值通道（`MetricDepth`/`InstanceId`/`HardwareDepth`）固定取 `time` 时刻的单帧，不随 `subframes` 变化。

### 语义与算法

- v1 实现：单帧 HDR + 运动向量重投影，按子帧时刻 `t_i = time + duration·(i+0.5)/N` 把上一帧/本帧辐亮度重采样 N 次求平均；相机位姿在子帧间按位置线性插值、朝向 slerp（只用于重投影，不重放几何）。
- 滚动快门：第 `v` 行的采样时刻为 `time + readout·v/height`；实现上按行偏移重投影，等价于逐行改变相机位姿。
- 权重：均匀驻留；总权重归一化，因此"曝光积分不改变平均亮度"是可断言的性质。
- 与 TAA 的关系：先积分再 TAA，TAA 的历史是积分后的结果；抖动仍只在无畸变空间。**TAA 不能代替曝光积分**：静止相机下模糊必须为 0，运动相机下模糊长度必须随 duration 线性增长。

### 验收门槛

1. **模糊长度**：相机横向 1 m/s、`duration=20 ms`、`fx=800`、目标距离 5 m，理论模糊 `1·0.02·800/5 = 3.2 px`；实测边缘 10%—90% 展宽与理论差 ≤ 0.5 px；`duration` 翻倍时展宽翻倍（±10%）。
2. **亮度守恒**：均匀白板积分前后的平均辐亮度差 ≤ 1%（权重归一）。
3. **静止为零**：静止相机 + 任意 duration，输出与 `duration=0` 逐字节相同（允许 ≤1 LSB 舍入，需说明）。
4. **TAA 不能代替**：同一运动、关闭曝光时边缘展宽 ≤ 1 px；开启后 ≥ 2.5 px。两条断言同时成立才算区分成功。
5. **滚动快门**：1 m/s、`readout=10 ms`、帧高 800 行，竖直边倾斜理论上 `1·0.01·800/5 = 1.6 px`；实测斜率误差 ≤ 0.3 px；全局快门同场景倾斜 ≤ 0.2 px。
6. **真值独立**：`MetricDepth`/`InstanceId` 在 `subframes = 1/2/4/16` 下逐字节相同；`Resolved` 的 A 分量明确标注非真值，几何真值请求不读它。
7. **确定性**：同输入同 subframes 两次运行逐字节相同；`duration=0` 时全部现有回归不变。

### 性能门槛

`exposure` pass（4 子帧）中位 ≤ 1.2 ms；16 子帧 ≤ 3 ms；全帧增量 ≤ 10%。若改为多子帧重放几何/光照，需另立里程碑并重定门槛。

### 不做

物体运动模糊（需逐物体速度通道）、景深/散景、卷帘快门与 TAA 的联合优化、机械快门抖动（曝光抖动）。

## F13 传感器噪声（M9）

### 范围

RGB 的光子散粒噪声 + 读出噪声 + 暗电流，深度的距离相关噪声；参数化、可复现、只作用于传感器输出。固定模式噪声/热像素/PRNU 不在本项。

### 接口

- `struct SensorNoise { float gain = 1; float readNoiseElectrons = 0; float darkCurrentElectronsPerSecond = 0; uint32_t seed = 0; float depthSigmaA = 0; float depthSigmaB = 0; }`，由相机或 `RenderRequest` 提供，进 `Observation`。
- v1 实现为 `SensorStage`（CPU，读回字节），派生输出 `noisy-color`（RGBA8）与 `noisy-depth`（R32F），不新增 `Channel`；真值通道逐字节不变。
- 单位：`gain` 为 e-/DN；输出 DN 的方差与均值都按 e- 计算后换算。文档给出换算公式，测试用两档 gain 验证线性。

### 语义与算法

- RGB：`DN = round((μ_e + N(0, σ_r²) + dark·t) / gain)`，其中 `μ_e = DN_signal · gain`，散粒噪声按方差 = 均值的高斯近似（μ_e ≥ 100 时误差可忽略；更小 μ 用泊松抽样）。
- 深度：`σ_z = depthSigmaA + depthSigmaB·z²`，单位米，`N(0, σ_z²)` 加到 `noisy-depth`；不写回 `MetricDepth`。
- 随机源：按 `(seed, 帧序号, 通道)` 做 64 位哈希后再用 PCG/Philox，逐像素独立；同一输入跨运行逐字节相同。

### 验收门槛

1. **统计**：512×512 均匀灰板（μ=2000 e-、gain=1、readNoise=2 e-），样本均值偏差 ≤ 1%，方差与 `μ + σ_r²` 的相对误差 ≤ 5%；`μ=50 e-` 时用泊松路径，均值/方差同样在 5% 内。
2. **正态性**：高 μ 场景的直方图 KS 检验 p > 0.01。
3. **gain 线性**：gain 翻倍时输出 DN 的方差降为 1/4（±10%），均值降为 1/2。
4. **可复现**：同 seed 两次运行逐字节相同；不同 seed 至少 99% 像素不同；改变帧序号结果不同（时间相关）。
5. **真值独立**：`MetricDepth`/`InstanceId`/`Color` 与无噪声帧逐字节相同；派生输出与源观测同时可读。
6. **深度噪声**：平面 z=5 m、`a=0.002, b=0.0004` 时，`noisy-depth` 在平坦区的标准差与 `a + b·z²` 差 ≤ 5%。
7. **边界**：零噪声参数时派生输出与输入逐字节相同（不能引入舍入漂移）。

### 性能门槛

1080p、两路派生输出的 CPU 处理 ≤ 15 ms；不新增全帧 GPU pass（v1）。GPU 化另立优化项，不阻塞本项验收。

### 不做

固定模式噪声、热像素、PRNU、卷帘与噪声的时序耦合、去噪、GPU 端实现。

## F14 雨雪（M10）

### 范围

雨/雪粒子的确定性生成、生命周期、透明度与深度策略；仿真时间驱动，静止相机下仍然运动。积水、湿润材质、体积雾不在本项。

### 接口

- `struct WeatherDesc { enum Kind { None, Rain, Snow } kind; float density; float fallSpeed; glm::vec3 wind; uint32_t seed; }`，进入场景快照（快照因此不可变，多相机一致）。
- 粒子状态是 `(time, seed, index)` 的纯函数，不依赖上一帧；这样多相机、乱序提交、重放都能一致。

### 语义与算法

- 生成体积：以相机为中心的长方体/圆柱，尺寸随 density 与类型派生；粒子越界即按周期回绕（等价于无限体积）。
- 渲染：instanced billboard/拖尾；雨为沿速度方向的细长条（长度 = 速度 × 曝光时长，F12 生效时自动变长），雪为带旋转的小片；深度测试开、深度写关。
- 深度策略：粒子写入专用标签位（现有约定为标签最高位）并标记 `groundTruth=false`；`MetricDepth` 保持背景/不透明物的真值，粒子的米制深度不混入真值通道。
- 运动向量写零并强制不复用旧像素（与点云同一策略），避免 TAA 拖影。

### 验收门槛

1. **时间驱动**：静止相机、连续两帧（time 不同）像素差异 ≥ 阈值；同一 time 两次提交逐字节相同。
2. **遮挡**：箱子后方的粒子不可见；对比移走箱子的同一像素，亮度差显著。
3. **深度语义**：`MetricDepth`/`InstanceId` 不出现粒子的米制深度；粒子标签的最高位为 1 且语义表标注非真值。
4. **密度**：可见粒子数与 density×体积 成正比（±10%）；density=0 时输出与无天气逐字节相同。
5. **TAA**：粒子运动不产生拖影——连续帧与单帧参考的差异只出现在粒子自身位置，历史复用被强制关闭（用活跃 pass 与画面双重断言）。
6. **确定性**：同 seed/同 time 跨进程逐字节相同。

### 性能门槛

1080p、1 万粒子中位 ≤ 1.5 ms；全帧增量 ≤ 8%。

### 不做

积水/湿润材质、雷电、体积雾/光柱、粒子与 TAA 的历史复用优化、GPU 粒子模拟。

## F15 3D Gaussian（M11）

### 范围

3D Gaussian Splatting 的导入、排序、投影、混合与深度语义。训练/优化不在本项。

### 接口

- 资产：`.ply`（位置、scale、四元数、opacity、SH0/1）导入为 `GaussianAsset`，按资产身份缓存（与网格一致）。
- 场景节点：`GaussianNode` 作为独立模块（不伪装成网格），主调度只遍历模块接口。
- 新增 `Channel::SplatDepth`（R32F）与 `Channel::SplatCoverage`（R8/R16F，alpha 累积），语义表 `groundTruth=false`。
- `Channel::MetricDepth` 不包含高斯：几何真值请求不渲染高斯。

### 语义与算法

- 投影：`Σ' = J W Σ Wᵀ Jᵀ`（W 为视图旋转，J 为投影雅可比），2×2 协方差取逆得椭圆；半径按 3σ 裁剪。
- 排序：每视图按中心深度做 GPU 桶排序（16 位键 + 平局用索引，保证确定性）；v1 只做一级/两级桶，不做 radix 全排序。
- 混合：front-to-back alpha 合成，`C = Σ c_i α_i Π_{j<i}(1-α_j)`；深度写"第一个 α ≥ 0.5 的样本"或 alpha 加权平均，二者择一并在语义中写明（v1 选 alpha 加权平均）。
- 与网格：高斯作为透明物体在不透明之后渲染，做深度测试但不写深度；与网格的相互遮挡依赖不透明深度，高斯之间的遮挡由排序保证。

### 验收门槛

1. **排序**：两枚前后已知的高斯，交换后颜色互换；三枚交叠按解析顺序合成，与 CPU 参考实现的每像素差 ≤ 1 LSB。
2. **协方差**：轴对齐、各向异性已知的高斯，投影椭圆长短轴与解析值差 ≤ 1%（含焦距变化的两种分辨率）。
3. **能量守恒**：opacity=1、无重叠的高斯中心像素等于其颜色（±1 LSB）；背景不受污染。
4. **深度语义**：`SplatDepth`/`SplatCoverage` 标注非真值；几何真值请求的活跃清单不含高斯 pass；`MetricDepth` 与不含高斯的帧逐字节相同。
5. **两相机**：同一快照两台相机各自排序正确，互不影响历史。
6. **历史失效**：高斯属性（位置/旋转/透明度）变化后 TAA 历史失效，旧内容不残留。
7. **确定性**：同输入两次运行逐字节相同（排序平局与归约顺序固定）。

### 性能门槛

1080p、100 万高斯中位 ≤ 8 ms（排序 + 光栅 + 混合）；全帧增量 ≤ 30%。规模翻倍时时间不超过线性 1.3 倍（给出扩展性证据）。

### 不做

SH 高阶（>1 阶）、动态/蒙皮高斯、训练流程、与网格的透明排序互通、DLSS 集成（F17 单独处理）。

## F16 真实感升级（M12，按子项立项）

本项不一次性开工。每个子项单独补规格、单独验收，未补齐的不得宣称"真实感提升"。

### F16a HDRI/IBL（首个子项，规格已补齐）

- 范围：等距柱状 HDRI 导入、漫反射/镜面预滤波（漫反射 SH9 或预积分贴图，镜面按粗糙度分级 mip）、重要性采样；方向光/点光保留。
- 接口：`EnvironmentMap` 资产（按身份缓存，随快照不可变）；`Scene.environment`；曝光仍由 `Color` pass 统一处理。
- 门槛：
  1. 常量环境（全白 HDRI）下，粗糙度 1 的球面漫反射辐亮度与解析值差 ≤ 2%；
  2. 镜面反射方向：镜面球在已知 HDRI 峰值方向上的高光位置误差 ≤ 1 px；
  3. 参考图 `example/preview/ref/ibl-courtyard.png`，SSIM ≥ 0.98（阈值首次实现校准后写回）；
  4. 关闭环境贴图时全部现有回归逐字节不变；
  5. `--validation` 0 条，预滤波 pass 无未初始化读取。
- 性能：预滤波一次性 ≤ 60 ms（离线可接受）；运行时 IBL 采样 ≤ 2 ms；全帧增量 ≤ 12%。

### 其余子项（各自补规格后才能开工）

- F16b 透明/半透：OIT 或加权混合二选一，需先定排序与深度语义、给出参考图与性能预算。
- F16c 软阴影/区域光：需先定光源面积、采样数与噪点/性能折中，给出参考图与 SSIM 门槛。
- 通用要求：每项都要有入库参考图、SSIM/PSNR 门槛、性能预算、缺陷注入记录；"看起来更好"不作为验收证据。

## F17 可选 DLSS（M13）

### 范围

在具备 SDK 与受支持硬件的机器上启用 DLSS；无 SDK/无硬件时保持 TAA 行为。DLSS 不能成为基础依赖。

### 接口

- 编译开关 `RENDERER_DLSS=OFF` 默认；打开后运行期探测 SDK 与设备能力，失败即回退，不抛异常终止。
- 协议：
  - 抖动序列与 DLSS 期望一致（Halton 2,3，像素单位，需给出与当前 TAA 抖动的换算）；
  - 运动向量沿用现有 `Channel::Motion` 约定（上一帧 UV 减当前 UV，无抖动投影，render resolution）；
  - 曝光：传 EV/scale 与 `SampleTime`，与 `Color` pass 的曝光参数同源；
  - 反转 Z 深度与 `reset` 标志（历史失效时置位）。
- 输出：DLSS 结果写 `Color`/`Resolved`，`MetricDepth` 等真值通道不受影响。

### 验收门槛

1. **无 SDK**：构建与全部 CTest 通过；同一场景与 TAA 路径逐字节相同（回退不留痕迹）；`package_check` 在无 SDK 机器上照常通过。
2. **有 SDK**：静止 5 帧后与 TAA 参考的 SSIM ≥ 0.99；运动场景无鬼影（运动前后帧的残差 ≤ 阈值，用参考实现对比）。
3. **运动向量符号**：相机右移时输出内容左移（方向断言），位移幅度与理论一致（±1 px）。
4. **曝光协议**：改变 exposure 的序列无闪烁（时间方差 ≤ 阈值）。
5. **reset**：相机跳转/资产变化后一帧内收敛，无旧内容残留。
6. **可选性**：默认构建不链接、不下载 SDK；CI 无 SDK 时 F17 相关测试跳过而非失败，并输出"skipped (no SDK)"。

### 性能门槛

1080p → 4K 上采样中位 ≤ 2 ms；全帧增量 ≤ 10%（相对 TAA 路径）。

### 不做

FSR/XeSS、帧生成、DLSS 与畸变的联合路径（畸变在 DLSS 之后的重采样里处理）、多 GPU。

GPU 遮挡剔除已按用户要求移除，不列入计划；保留 CPU 视锥剔除。完整 three.js API、全部 glTF 扩展和多 GPU 不属于当前承诺。
