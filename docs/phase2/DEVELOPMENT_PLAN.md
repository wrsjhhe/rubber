## 各任务必须保留的边界

S2-00：核查而非假定 staging 回收已修复；在固定有界工作负载下，完成 GPU 工作并释放结果后，pendingUploads/stagingBytes 应回到基线。针对 M6 保留性测试比较文件清单及哈希，让哨兵实际经过受测分支。真实安装前缀仍只读，不用删除它制造负例。

S2-01：先提交最终接口和两阶段调用示例，再写算法。旧 SensorStage 适配器只能读取原始观测，新增阶段可读取声明的派生输入。不要用字符串查找后强转格式代替类型校验。

S2-02：绘图展示只是辅助，必须以解析点和误差分布验收。无效区、主点偏移、fx≠fy、非方形输出必须有用例。

S2-03：首版同步逐样本流程即可，不增加后台线程或改写 submit 的非阻塞语义。先用静态快照和解析运动轨迹验证，再接动态场景。公开最终平均图与参考真值，时间样本原图可仅作为测试诊断，不默认长期保留。

S2-04：先固定 PRNG 版本与参数单位，再编写噪声。必须区分关闭模型与参数为零；统计门槛见 VALIDATION，不因一张“看起来有噪声”的图验收。

S2-05：传感器示例支持配方选择、参数/种子、双相机和无窗口运行；导出图像/原始数值文件及 JSON 元数据。资产验证 CLI 接收当前已支持的静态 glTF/GLB，报告加载成功/失败、包围盒有限性、有效几何覆盖与深度范围；规则与退出码明确，空场景/缺资产为诊断失败。它不是资产物理正确性的自动认证工具。

## 本轮不顺带实现

滚动快门、GPU 处理链、天气、高斯、IBL、透明、DLSS、多队列、显存别名和 GDS 适配保持独立。发现基础缺陷先记录其对当前任务的影响，只有阻塞本轮正确性/资源安全时纳入修复。

## 交接要求

每项提交：功能编号、最终接口、变更文件、测试命令/退出码/日志、数值结果、失败路径、已知缺项、迁移说明。对关键防线做定向缺陷注入：先说明注入点，确认测试失败，再还原并验证工作树。不得提交注入代码。审核者独立复测后更新 PROGRESS，不由开发者自行标记验收。
